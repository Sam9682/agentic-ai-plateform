## Classification decision rules (ordered)

Each row gets exactly one value, decided in this order (first match wins):

1. **NOT_APPLICABLE** — the sub-feature does not apply to this codebase's chosen design (the row records why).
2. **NOT_IMPLEMENTED** — no source file implements it; `Source File(s)` is `—` with a note on where it would live.
3. **IMPLEMENTED_AND_VERIFIED** — a source file implements it **and** a covering test **passes (non-blocked)** in the task-7 Baseline_Result. A blocked covering test cannot yield `_VERIFIED`.
4. **IMPLEMENTED_BUT_INCOMPLETE** — core behavior exists but has known gaps/TODOs, **or** the covering test is blocked/absent so the behavior is unverified.
5. **PARTIALLY_INTEGRATED** — the component exists (and may be unit-tested) but is not wired into the end-to-end flow (e.g. a service with no route/consumer calling it — per the `02` no-inbound-import findings).

### Baseline_Result basis for `_VERIFIED` (from artifact 07)

The task-7 baseline recorded **254 pytest passed, 4 pre-existing failures, 3 skipped**; node `tests/js/` 150/150; bash 57/0. The 4 pre-existing failures are 3 by-design Traefik Docker-API-version bug-condition cases + 1 Hypothesis-falsified SHAI chat route (`src/routes/genai_routes.py`) — **none** of them cover an ARO/ZAF/OBS sub-feature, so they do not block any `_VERIFIED` rating below. The `Blocked_Check`s are the `integration`-marked tests (incl. `test_e2e_governed_scenario.py`, live Traefik/Docker) and DB-coupled `scripts/test_*.py` (live PostgreSQL); a sub-feature whose only covering test is one of these cannot be `_VERIFIED`.

## Summary of findings (handoff to artifact 10)

- **Verified today (5):** ARO agent registry; ZAF policy engine (PDP) and approval service; OBS runtime behavior and agent behavior. These rest on passing, non-blocked unit/property tests in the Baseline_Result.
- **Implemented but incomplete (13):** the bulk of ARO (lifecycle, adapters, execution manager, sessions, runtime registry, task store) and all of the Infrastructure Orchestrator (remote execution, scheduler, reconciliation, connectors). Gaps are internal (timeout/retry/cancellation/session enforcement, protocol coverage) or verification is a `Blocked_Check` needing live services. → Phases 2 (ARO completion) and 4 (runtime execution).
- **Partially integrated (7):** the ZAF enforcement path (action interceptor, PEP/PDP split, credential broker, audit) and the OBS detection pipeline (classification, anomaly rules, loop detection). Each component exists and is unit-tested but has **no inbound `src/` consumer** (per `02`), so it is not wired end-to-end. → Phase 3 (ZAF hardening/wiring), Phase 5 (OBS pipeline), Phase 6 (integration & E2E).
- **Not implemented (5):** OBS cost, and the entire Agent Supervisor (roles, task decomposition, delegation, governance inheritance). → Phase 5 (OBS & Agent Supervisor).
